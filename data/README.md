# Data

- `raw/harbor_parity/`: the 84 `parity_experiment.json` files from the Harbor repository at commit `dc933be707feafbb9efcdf092cb8a0e391332617` (2026-10-10), one per adapter, unchanged. `raw/MANIFEST.json` holds a SHA-256 per file; `tests/test_phase0.py` checks them.
- `raw/ADAPTER_CONTRIBUTING.md`: Harbor's adapter guide at the same commit; Step 5 states the range-overlap matching criterion.
- `paper/tables_3_4.csv`: Tables 3 and 4 of arXiv 2609.04298 v3 (parity results per adapter), parsed by `scripts/p1_parse_paper_tables.py`.
- `pertask/<adapter>/{original,harbor}.csv`: per-task outcomes (`run, task_id, reward`) for the primary experiment of each adapter, recovered from the Hugging Face dataset `harborframework/parity-experiments` with `scripts/pertask/<adapter>.py`. The analysis scripts read only these two files.
- Extra per-task files with the same columns: `original__<model>.csv` and `harbor__<model>.csv` hold further experiments of the same adapter (one each for bfcl, swebenchpro and swegym; two for devopsgym). featbench has `harbor__<agent>-<model>.csv` for two further experiments recovered on the Harbor side only. bfcl also has `original_llm__<model>.csv` and `original_json__<model>.csv` for two further original-side handlers. Each adapter's `experiments_covered` entry in the manifest says which experiment each file holds.
- `pertask/MANIFEST.json`: per adapter, the files used, the formats, whether the recovered run means reproduce the published run scores, and which analyses the adapter enters. `recovery_method` states how files were chosen from the dataset and the download limits. `not_recovered` lists the one adapter with a parser but no per-task files here (strongreject) and the reason.
- `pertask/commit0/harbor.csv` (Harbor side only, 3 runs x 16 tasks, from `scripts/pertask/commit0.py`) has no manifest entry and enters no analysis. commit0 has no `parity_experiment.json` in the pinned snapshot, and its original-side files hold only aider transcripts with no evaluation output.
- `external/` is named in some manifest notes. It is a local download cache that git does not track. Its paths mirror the dataset layout: `external/hf/<hf_name>/` holds the files fetched from `adapters/<hf_name>/`. Each `scripts/pertask/<adapter>.py` takes such a folder as its first argument.
